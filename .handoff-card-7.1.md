```ts
async compact(reason: 'auto' | 'manual' = 'manual'): Promise<void> {
  if (this.#isIterating) { throw new Error('Cannot call compact() while iterate() is in progress — see the Mid-run safety note in the README.'); }
  await this.#performCompaction(reason);
}
async #performCompaction(reason: 'auto' | 'manual'): Promise<void> { /* the existing body, minus the guard */ }
```
The mid-run trigger calls `#performCompaction('auto')` directly between cycles (safe: no SDK stream
active there). Run-end keeps calling `this.compact('auto')` (it clears `#isIterating` first at ~2925).

### B. Add window-resolution + real-token threshold helpers (private methods on the class)
```ts
private async resolveContextWindowTokens(): Promise<number> {
  if (this.opts.contextWindowTokens !== undefined) return this.opts.contextWindowTokens;
  let live: number | null;
  try {
    live = await MODEL_CONTEXT_LENGTH_CACHE.get({
      model: this.opts.model, apiKey: this.opts.apiKey,
      ...(this.opts.baseUrl !== undefined && { baseUrl: this.opts.baseUrl }),
    });
  } catch { live = null; }
  if (live !== null && live > 0) return live;
  return getModelContextWindow(this.opts.model, this.opts.modelContextWindows);
}

// Decide whether observed REAL input usage crosses the token threshold.
// realInputTokens: server-reported usage.inputTokens (null on first turn → estimate).
private async shouldCompactForRealTokens(realInputTokens: number | null, messages: unknown): Promise<boolean> {
  const window = await this.resolveContextWindowTokens();
  const thresholdTokens = resolveCompactionThresholdTokens(
    this.opts.compactionThreshold, this.opts.model, this.opts.modelContextWindows,
    { ...(this.opts.outputReserveTokens !== undefined && { outputReserveTokens: this.opts.outputReserveTokens }),
      ...(this.opts.safetyBufferTokens !== undefined && { safetyBufferTokens: this.opts.safetyBufferTokens }) },
  );
  // NOTE: resolveCompactionThresholdTokens uses getModelContextWindow internally for the window;
  // to honor the LIVE window you must instead compute the threshold from `window` directly.
  // Simplest: inline the reserve/buffer math here using `window`, OR add a window param to the
  // resolver. Recommended: compute threshold = max(floor(window*0.25), window - reserve - buffer)
  // here, mirroring the reserveOpts branch, so the live-looked-up window is actually used.
  const observed = realInputTokens !== null && realInputTokens > 0
    ? realInputTokens
    : Math.ceil(estimateMessagesCharLength(messages) / CHARS_PER_TOKEN)
      + estimateInstructionsAndToolsTokens({ instructions: this.opts.instructions, tools: this.opts.tools });
  return observed >= thresholdTokens;
}
```
**IMPORTANT design note:** `resolveCompactionThresholdTokens` resolves the window *internally* via
`getModelContextWindow(model, overrides)` — it does NOT accept a pre-resolved window. For the LIVE
`/models` window to actually take effect, either (a) compute the absolute-buffer threshold inline in
`shouldCompactForRealTokens` from the live `window` value, or (b) add an optional explicit-window
param to `resolveCompactionThresholdTokens`. Option (a) is simplest and avoids touching the merged
resolver's signature again. Make sure an explicit `compactionThreshold` STILL wins outright (return
`compactionThreshold` verbatim before doing window math).

**Back-compat with the existing `tokenCounter` path:** Keep `isOverCompactionThreshold(messages)` as
the run-end check when there is NO real `usage.inputTokens` to consult and a `tokenCounter` is set —
OR unify. Cleanest: the mid-run/run-end trigger should prefer real `usage.inputTokens` (Card 7.1's
whole point), fall back to `isOverCompactionThreshold` (tokenCounter/char path) when no usage sample
exists. Decide and document in the PR body. The simplest coherent rule:
- explicit `compactionThreshold` set → that path wins (chars if no tokenCounter, tokens if tokenCounter — preserve merged semantics for run-end; for mid-run, treat as tokens vs real inputTokens).
- else if real `usage.inputTokens` available → token threshold from resolved window (absolute-buffer).
- else → `isOverCompactionThreshold(messages)` (existing tokenCounter/char fallback).

### C. Mid-run trigger (Codex-style option (a) — REQUIRED by user)
"On threshold crossing, mark and compact at the top of the next turn within the same `iterate()`,
keeping the existing mid-iterate `compact()` guard semantics intact."

- Hoist `let pendingMidRunCompaction = false;` to the iterate() method scope (next to
  `let finalUsage` ~line 1643) so the `finally` block can read it.
- In the multi-turn loop (`while (true)` ~line 2240), at the TOP of the loop body (before pulling the
  next input), if `pendingMidRunCompaction` is set: clear it, and if `this.opts.autoCompact &&
  persistSession`, `await this.#performCompaction('auto')` inside try/catch (log
  `'Mid-run auto-compaction failed'` on error). The shared state accessor means the next cycle's
  `callModel({ state })` resumes from the condensed history automatically — do NOT reassign `state`
  (it's the accessor, a const at ~line 1791).
- After the per-cycle `deriveCompletionStatus` (agent.ts ~line 2768), BEFORE the
  `if (cycleStatus === 'max_budget' || 'max_turns') break;`, run the threshold check for ALL non-error
  cycle exits and set `pendingMidRunCompaction = true` when it crosses. Use real input tokens:
  `const realInputTokens = typeof finalUsage?.inputTokens === 'number' ? finalUsage.inputTokens : null;`
  Gate on `this.opts.autoCompact && persistSession`. Wrap in try/catch logging
  `'Mid-run compaction threshold check failed'` (warn) — must never break the live run.
- IMPORTANT (avoid double-compaction): the run-end `finally` block must NOT independently re-evaluate
  the threshold. Make run-end compaction fire ONLY when `pendingMidRunCompaction` is still set at loop
  exit (i.e. the last cycle crossed the threshold but no subsequent cycle consumed the flag — e.g.
  max_turns exit or input exhaustion). This collapses mid-run + run-end into one signal and prevents
  compacting the same history twice. See the stale-WIP branch for the exact pattern that passed tests.
